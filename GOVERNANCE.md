# Governance

Sparelay is maintained by the maintainers listed in
[MAINTAINERS.md](MAINTAINERS.md).

## Decision making

- Small changes are decided in pull requests by the maintainers.
- Larger changes, such as new provider categories, breaking API changes, or
  changes to the release process, should start as an issue so the design can be
  discussed before implementation.
- Maintainers aim for rough consensus. If consensus cannot be reached, the
  maintainers make the final decision and document the reasoning in the issue
  or pull request.

## Releases

Releases follow [Semantic Versioning](https://semver.org/) and are generated by
release-please from Conventional Commits. Maintainers merge the release pull
request; the publish workflow builds and pushes the Docker image.

## Becoming a maintainer

Contributors who consistently submit high-quality changes, help review pull
requests, and support users may be invited to become maintainers. There is no
fixed contribution count; sustained, constructive participation is what matters.

## Security

Security reports are handled privately according to [SECURITY.md](SECURITY.md).
Please do not discuss undisclosed vulnerabilities in public issues or pull
requests.
